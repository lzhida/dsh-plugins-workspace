# 内嵌 skill `kanban-task-create` 与用户级 `dsh-task-create` 的差异对照

本包内嵌 skill（`SKILL_NAME = 'kanban-task-create'`，正文见
`src/skill/skill-content.ts`）以用户级
`dsh-task-create` skill（front matter + 正文共 562 行）为基底忠实搬运，
只做了三类改动：**改名与归属声明**、**环境表述本地化**、**能力补齐**。
本文档逐节列出差异，供审查与后续维护对照。

## 三、删除清单（仅环境性表述）

- 「skill 文件位于 ~/.dsh/skills/…（provider user-dsh / rank 400）」的目录级描述；
- 「第一道防线是 ~/.dsh/skills/ 目录隔离」「防止被复制回 ~/.agents/skills 误触发」等依赖用户本机目录布局的表述；
- 所有用户本机绝对路径（正文无 `C:\Users` 形态路径，本卡亦未引入）。

门禁**语义**完整保留：会话工具清单没有 `taskboard_*` 工具 → 立即停止，
不模拟建卡；该判定改为「适用性由会话工具清单决定」，不再依赖目录隔离这一外部前提。

## 四、能力补齐（原版没有、内嵌版新增）

1. **插件版本探测（两层判据）**：层 1——taskboard_* 工具 schema 含 `blockedBy`
   ⇒ 插件 ≥ 0.10.0，版本支持依赖门禁；层 2——插件 0.10.1 起还要确认依赖总开关
   `dependenciesEnabled` 处于开启态（缺省值随插件版本与安装形态而定，以探针实测为准），
   否则 `blockedBy` 会被静默丢弃、门禁不生效，降级为文字兜底（在卡文与 prompt
   里写明先后顺序与前置卡 id）。
2. **建卡字段取舍显式化**：`permission` / `model` / `execution` / `presetId` /
   `isolation` 一律省略、跟随看板默认，绝不代设（原版散落在 §4/§6，内嵌版在
   §4 与 §6 各自点明）。

## 五、优先级口径

- **看板模式会话内**：以本内联版（`kanban-task-create`）为准——它随
  `@zhidal/dsh-kanban-mode` 预设分发、按看板模式红线本地化。
- **用户级副本**：可继续保留，但在看板模式会话中其建卡职责已被本内联版取代；
  两份副本并行维护会漂移（同一套规范改一处漏一处），**建议停用或清空用户级
  `dsh-task-create` 的建卡职责**，仅保留其历史参考价值。
- 维护纪律：后续对建卡规范的修改应落在 `src/skill/skill-content.ts` 并同步更新
  本文档的差异表，不要再改用户级副本（或至少在本表登记该分叉）。
- 例外登记（2026-11-26，上游同步系列 5/6）：本卡因「依赖总开关两层判据」同时修订了
  用户级副本 `~/.dsh/skills/dsh-task-create/SKILL.md`（§0 探测拆两层、新增 4.11.0、
  4.11.6 扩为「插件 < 0.10.0 或 ≥ 0.10.1 但总开关关闭」、硬约束与 Verification 补前提），
  以消除两侧说法分叉；用户级副本措辞取通用版（缺省值随安装形态而定、以探针实测为准），
  内嵌版保留本仓 vendored 的具体缺省（开启，见 `plugins/dsh-taskboard/src/shared/dependencies.ts`）。
