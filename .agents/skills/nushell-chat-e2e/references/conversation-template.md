# 单句 goal 对话模板与构造规则

## 构造规则（全部满足才可发送）

1. **单条消息**：官方 `/goal` 命令 + 全部 12 项要求，一次性发送（`/guided-goal` 因 Web client 集成需构建产物，暂不入 e2e 组合）
2. **禁词**：全文不得出现 "nushell"（大小写任意形式，**含 BASE_DIR 路径**）；用「结构化 shell 工具」指代
3. **反漂移约束**：显式禁止 bash/pwsh 工具——否则模型可能用其他 shell 工具完成任务，测试失效
4. **五字段齐备**：草稿自带成功标准（12 项期望值）、验证方式（逐项对照）、迭代上限（5 轮）、范围边界（只在 `<BASE_DIR>` 写文件）、停止条件（无法达成即停 + 总结格式）——`/goal` 直接以此创建并自主执行
5. **硬校验值内嵌**：55、5.5、42、e2e-42 等直接写进对话
6. 工作目录 `<BASE_DIR>` 发送前替换为真实独占临时目录（命名不含禁词）

## 模板

```
/goal 请完成以下 12 项 shell 能力验证,全部通过或触发停止条件后输出逐项对照表(每项:命令、实际结果、通过/失败)。先创建工作目录 <BASE_DIR>,所有文件操作仅限该目录内。各项要求与期望结果:
1. 基础文件操作:在 <BASE_DIR>/fs 下创建文件 hello.txt 写入内容 e2e-ok,重命名为 hello-renamed.txt,读回验证内容必须等于 e2e-ok,最后删除并确认文件已不存在;
2. 排序过滤:在 <BASE_DIR>/sort 下创建 a.txt(3字节)、bb.txt(200字节)、c.md(50字节),按文件大小降序列出并只保留 .txt 文件,结果必须恰好是 bb.txt 在前、a.txt 在后,不得出现 c.md;
3. 结构化解析:写 <BASE_DIR>/data/team.json 内容 {"team":[{"name":"alice","score":90},{"name":"bob","score":70}]},读取后给出全部姓名(必须是 alice 和 bob)与记录数(必须是 2);再写 <BASE_DIR>/data/rows.csv 含表头与 2 行数据,数据行数必须是 2;
4. 系统信息:给出当前用户名(必须非空)、确认 PATH 环境变量存在、列出进程且进程数不少于 1;
5. 外部命令:调用外部程序 git --version,输出必须以 git version 开头并带版本号;
6. 错误处理:尝试读取 <BASE_DIR>/nonexistent.txt,必须得到明确错误信息而非崩溃,且之后命令仍能正常执行;
7. 管道求值:对 1 到 10 的整数序列求和与求平均,和必须等于 55、平均必须等于 5.5;
8. 格式转换:把 {"a":1,"b":"x"} 从 JSON 转为 YAML(必须含 a: 1)再转回 JSON(a 必须等于 1);
9. 字符串处理:插值表达式 e2e-(6*7) 的结果必须是 e2e-42,Hello World 转小写必须是 hello world,a,b,c 按逗号拆分必须得到 3 个元素;
10. 日期时间:格式化当前日期取年份,必须等于 <YYYY>;计算当前时刻距 <YYYY>-01-01 的时长,必须是正值;
11. 自定义命令:定义函数 add-two(接收整数返回其加 2 的结果)并调用 add-two 40,结果必须等于 42;
12. 写出回读:把表格 [[a, b]; [1, 2]] 保存为 <BASE_DIR>/out/table.json 再读回,a 必须等于 1 且 b 必须等于 2。

约束:全程统一使用本会话可用的结构化 shell 工具执行(禁止使用 bash、pwsh 工具);迭代上限 5 轮;只允许在 <BASE_DIR> 内写文件;任一项无法达成时停止并如实报告失败项。
```

- `<YYYY>` 按测试执行日年份替换（2026 年测试即 `2026`）
- 模板变更时必须同步 `scenarios.md` 与 `review-protocol.md` 的期望值

## 发送方式（实测有效路径）

1. 浏览器打开 tokened URL → 点击聊天输入框
2. **真实键盘**输入 `/goal`（`execCommand`/`insertText`/paste 事件会被编辑器回滚或扰乱内部状态——必须真键盘；puppeteer 键盘经 `tab.run` 的原生 `page.keyboard` 可用）
3. 指令弹窗过滤出 `goal 设置或查看长期任务目标` → 按 **Enter** 选中（编辑器进入 goal 命令模式，占位提示「输入目标，智能体将持续执行」）
4. 键入**单行**目标正文（换行改空格；Enter 会触发发送，正文里不能按 Enter）
5. 点击「发送消息」按钮（避免按 Enter）

## 消息形态

- 用官方 `/goal` 命令（goal 域），非 `/guided-goal`：发送成功后 UI 出现 `Goal created. Status: active` 与「进行中的目标」栏
- **禁词自检**：发送前对最终文本断言 `/nushell/i` 不匹配（含 BASE_DIR 路径）
- 单行正文 = 模板各行以空格连接；`<YYYY>` 按执行日年份替换
- 模板变更时必须同步 `scenarios.md` 与 `review-protocol.md` 的期望值

## 发送后

- goal 创建回合模型输出五字段摘要后**立即结束**（协议行为），随后 goal 自主多轮执行——**等待期间不要追加消息干扰**
- 执行耗时数分钟（12 项 × 每项工具调用），轮询页面快照直至出现最终逐项对照表
