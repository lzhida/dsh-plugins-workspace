# 审查协议：证据采集与逐条判定

## 证据采集（goal 结束后）

1. `take_snapshot`（a11y 文本快照）抓取完整会话内容——包含模型回复与工具调用块
2. 关键节点 `take_screenshot` 留证（goal 创建确认、最终总结）
3. 需要精确文本时用 `evaluate_script` 读消息 DOM 的 `textContent`
4. 工具触发证据 = 会话中出现以 nu 语法执行的工具调用（`1..10 | math sum`、`def add-two` 等 POSIX shell 无法直接执行的形式）；仅凭最终总结文字不算

## 逐条判定规则

每项 **pass** 必须同时满足：

- **A 工具触发**：会话证据显示该项命令经结构化 shell 工具执行（nu 语法形态）
- **B 结果命中**：应答文本包含 `scenarios.md` 中该项硬校验期望值

只满足 B（如模型心算出 55 没跑命令）→ 判 fail（工具未触发）。

## 失败分类（审查表「备注」列）

| 分类 | 含义 |
| --- | --- |
| 工具未触发 | 模型用了 bash/pwsh 或未调用工具直接回答——被测能力失效 |
| 命令失败 | 工具被调用但命令报错（记下 stderr 关键行） |
| 结果错误 | 命令执行成功但结果 ≠ 期望值 |
| 未执行 | goal 提前停止，该项未触达 |
| 证据不足 | 会话快照无法定位该项命令与结果（补 `evaluate_script` 采证） |

## 报告格式

```
| # | 场景 | 工具触发 | 期望 | 实际 | 判定 | 备注 |
12 行 + 总结行（N/12 通过）
```

- 任一 fail：附原始证据片段（命令 + 输出），不下「大概没问题」结论
- goal 最终总结缺失逐项对照表 → 本身记为流程缺陷（guided-goal 协议第 5 条要求输出总结）

## 与插件激活证据的关系

审查表只覆盖「对话 → 工具 → 结果」；插件激活证据（运行器日志 token + 设置页「已启用」）在 SKILL.md 流程第 1-2 步单独确认，两者都齐才算完整通过。
