# @zhidal/dsh-patent

「**专利交底**」预设 bundle：协助**发明人**撰写技术交底书（中国专利），交付一份专利
代理师能看明白的交底书。安装后 Web 新建会话的预设选择器出现「专利交底」。

## 组成（一个包，两个插件行）

| 行              | 入口                            | 内容                                                                         |
| --------------- | ------------------------------- | ---------------------------------------------------------------------------- |
| `dsh-patent`    | `./src/index.ts`                | 六个模型工具 + 三个结构化 prompt section + 内嵌方法论 skill（撰写/审查两份） |
| `preset-patent` | `@deepseek-ai/dsh-agent-preset` | 「专利交底」预设：发明人助手 persona + 检索/文件/office skill 链 + 压缩组    |

## 模型工具

- **`disclosure_template_fill`**：按交底要点产出内容 markdown（头部字段 + 七部分），
  返回内置模板绝对路径与交付指引。`delivery` 三选一：
  - `builtin-docx`（默认）：内置去公司化模板（`assets/disclosure-template.docx`），
    经捆绑 python-docx 填充，保留模板格式；
  - `user-docx`：用户提供模板 → 按一、…七、标题定位填充，找不到的部分提醒用户手工补位；
  - `markdown`：直接写 .md 文件，用户自行填写。
- **`disclosure_check`**：交底书合规检查——七部分齐全、头部占位提醒、第三部分公开
  充分度启发式（同领域技术人员可实施标准，全占位骨架同样提示）、技术问题主次结构、
  残留占位扫描；初稿高发问题检测：同源文本重复度（全文两段公共后缀 ≥100 字、
  第三↔第五部分成对复用段落 ≥40 字）与「所述X」术语互为包含的一词多义信号。
- **`patent_claims_check`**：权利要求结构校验（编号连续、从属引用在先、多项从属不
  嵌套、主题一致、其特征在于），服务「六、需要保护要点」的权利要求式表述；介质/
  设备权对方法权利要求的类型引用（「执行/实现权利要求 N 所述的方法」）按公布文本
  变体识别，不误判为从属引用。
- **`claims_evidence_check`（审查侧源码对账）**：以权利要求为行、说明书与
  源码为证据的三方对账引擎。模型先读码取证据，再把逐特征记录（权项位置 / 特征
  原文 / 说明书位置 / 源码锚点 / 四态判定 / 建议）提交给工具；工具强制证据纪律
  （无 `文件:行号` 锚点的判定一律拒绝输出）、检查每条权项的覆盖完整性、识别
  「同一特征在权项与说明书归到不同载体」的矛盾、评估从属链退守风险（引用基准
  并列分支 + 链上失实污染），并渲染可直接当修改清单用的对账矩阵（JSON +
  markdown）。报告开头先给「待核对清单」——按常量 / 路径 / 枚举 / 函数名 / 层级序 /
  分支数六个维度从权项文本抽出的源码核对线索（清单只提示「该查什么」，不代表
  任何判定）。四态判定：可主张 / 需改写 / 不可主张（源码无落点或行为相反，主张
  即自曝破绽；判定为不可主张但严重度低于 high 时告警 `SEVERITY_MISMATCH`，不
  拦截）/ 未覆盖（源码有实现但权项未记载 = 保护缺口；此类记录建议挂
  `claimNo=null`）。工具不读源码、不替模型断言——锚点必须真实。
- **`draft_review_check`（审查侧初稿审查主工具）**：复核代理师初稿，输出分级问题
  清单（严重 / 高 / 中 / 低 / 建议），每条含位置 / 问题 / 依据 / 建议。输入可以是
  初稿 docx 路径（工具内含最小 zip 解析，只读正文），也可以直接给摘要 / 权项书 /
  说明书 / 附图文本。`focus` 裁剪检查面：`comply`（默认，形式规范 + 符合性）/
  `formal`（权项结构、说明书五部分、摘要字数、附图标记体例、发明内容↔权项逐字
  对应、术语纪律、绝对化措辞、逐字重复度）/ `prior-art`（只出核查清单）/
  `strategy`（从属链退守风险）。**只机检能机检的**：数值事实、图面语义、现有技术
  检索这类需要人判断的项不写成结论，而是返回一份「待模型判断的核查清单」；接入
  `claims_evidence_check` 的证据记录后，还会报「权项特征无源码落点」与从属链失实
  污染风险。两个可选入参把对账链路接齐：`disclosurePath` 读入交底书文件（与摘要 /
  权项书 / 说明书 / 附图一起参与逐字重复度交叉比对），`sourceRoot` 列出源码目录
  下的文件清单（跳过 `node_modules` / `.git` / `dist` 等依赖目录）供模型逐条读码
  对照——工具仍不读码、不替模型断言，命中与否由模型读码后经证据记录回填。
- **`claims_code_map`（审查侧维权取证台账）**：把 `claims_evidence_check` 的同一批
  证据记录重新组织成**出海维权证据链对照表**（权项特征 ↔ 源码落点）——判定核心与
  2/5 共用同一套四态，不另写一套判定逻辑，只做呈现与再组织。输出八节：
  ①四态分区（可主张 / 需改写 / 不可主张 / 未覆盖）；②两张风险专章——「不可主张
  （主张即自曝）」与「未覆盖（保护缺口）」；③答辩锚点（可主张且属组合特征，附
  检索风险评估位：低适合作锚点、高不宜）；④代码侧资产台账（源码有、权项无保护
  点逐条列出，附源码锚点与建议的权项落点形态，工具不代拟权项文字）；⑤双载体特
  征提示（同一特征多处主张 / 资产规模与权项表述不匹配）；⑥我方是否实施该权项自
  检（逐特征标注，未覆盖者标为潜在无效宣告与反制暴露面）；⑦从属链失实传导；
  ⑧诊断。每条映射含权项位置（按分号级步骤定位，如「权利要求 1 · 步骤 2/3」；特征
  原文长于步骤文本时标为「（启发式定位）」）、特征原文、源码锚点、状态与建议。入参
  支持权项文本或权项文件路径（两者同传以文本为准并记歧义警告）、证据记录、源码根
  目录清单（只列清单不读码；目录下无文件时记警告，不据此断言任何特征未覆盖）。
  **输出是技术事实核对结果，不是法律意见**：FTO / 侵权比对结论由律师判断；报告标注
  锚点生成时间戳并提示锚点随代码演进而漂移、取证前需复核。

  维权取证用法：先用 `claims_evidence_check`（或 `draft_review_check`）读码取到
  逐特征证据记录，再把同一批记录交给 `claims_code_map` 出台账——四态判定不重算，
  同一份证据在「审查问题清单」与「维权取证底稿」两种视角下各出一张表。

## 内嵌方法论 skill

插件按需注入两份方法论 skill（`source: 'bundled'`，模型可在会话中自行加载，
卸载插件即注销）：

- **`patent-disclosure`（撰写侧）**：技术交底书撰写方法论——七部分结构、公开充分
  标准、CNIPA 措辞参考与 docx 交付路径。触发场景：起草、补写或交付交底书。
- **`patent-draft-review`（审查侧，0.2.0）**：代理师初稿复核方法论——24 视角交叉
  审查拓扑（合规 A10 / 源码对照 B7 / 交底书对照 C3 / 战略 D4）、两条定权规则、
  收敛纪律（断言必须挂源码 `文件:行号` 或文档条目）、纠错纪律（预判被证伪即以
  代码事实撤回）与轻量档/全量档裁剪规则。触发场景：复核代理师初稿、权项-源码
  对账；不适用于撰写交底书或纯形式校验。

## 公司信息

插件设置（`disclosureDefaults`）存一次默认值（申请人/联系人/电话/邮箱/内部案号）；
用户显式提供的值优先；两者皆无时产出占位「〔…：请填写〕」并提醒用户自行修改。

## 开发

```sh
pnpm --filter @zhidal/dsh-patent typecheck
pnpm vitest run packages/dsh-patent
pnpm --filter @zhidal/dsh-patent build   # esbuild → dist/index.js（实体安装/发布必需）
```

发布形态为构建式（`main` 指 `dist/index.js`，源码入口无法实体安装）：改动源码后
先 `build` 再重启实例；`pnpm pack` / `prepare` / `prepack` 自动构建。

e2e（真实 dsh 实例四步流程）见仓库 `.agents/skills/dsh-plugin-dev/SKILL.md` §5。
