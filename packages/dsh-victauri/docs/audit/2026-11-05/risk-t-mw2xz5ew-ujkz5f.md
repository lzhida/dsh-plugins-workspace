## 二、残余风险（均为记录性，无需新建卡）

- **R1｜上游别名清单会随版本变化**：本卡登记的是 0.8.8/0.10.2/0.10.3 三个已核版本的 serde alias 集合；若上游新增/移除别名，插件描述会滞后。处理方式：随上游版本升级重新核 crate 源码（路径见上游反馈材料「证据来源」段）。
- **R2｜文档层证据本机未逐行复核**：别名标注的**文档层**现状（tools-reference.md 各行号）来自抓取副本与上游 raw 双路比对，非本机 crate 内复核（crate 不含 docs/）；**源码/schema 层**（serde alias 集合）已 100% 本机复核。
- **R3｜本地归一与上游别名并存**：模型若同时传 query 与 sql，插件在 bridge.ts ARG_ALIASES 归一阶段移除 sql，不会触发上游 duplicate field；但直接绕过本插件调上游时仍会触发该错误。此行为属上游语义，本卡只做描述澄清，未改运行时逻辑。
- **R4｜改动仍以描述与文档为主，但已补行为级护栏**：本卡的运行时逻辑未变（ARG_ALIASES 与归一流程原样保留），但本卡把「本地归一保留 query、移除 sql」升级为对外承诺，故已补 query_db 归一的行为级用例（src/tools/standalone/standalone.test.ts:117）；其余断言锁文案事实（来源标注、别名登记、事实锚点与文档口径）。
- **R5｜round-\*.md 历史轮次文档按当时口径保留**：早期 round 文档中关于 sql 别名的表述属历史记录，不回改；最新结论以 gap-list.md 的勘误段与本文为准。
- **R6｜bridge.ts:112 旧注释与上游事实不符（信息项，本卡禁改其运行时逻辑故未动）**：注释写「别名键总是移除(服务端拒未知字段)」，但 0.8.8/0.10.2/0.10.3 三版 crate 全仓 `deny_unknown_fields` 零命中——上游**不拒**未知字段，移除别名键的真实理由是避免 serde duplicate field。该注释属本卡之前遗留、且与 M-4（未知参数静默透传）同域，已记入 backlog-A（t-mw2eut5k-6k1elc）的线索，随该卡一并处理。
